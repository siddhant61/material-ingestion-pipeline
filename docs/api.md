# Material Ingestion Pipeline API Documentation

This document provides comprehensive API documentation for the Material Ingestion Pipeline, designed for developers integrating with its functionalities. The API allows for initiating, monitoring, and retrieving results from the material ingestion process.

## 1. Overview

The Material Ingestion Pipeline API provides programmatic access to the core ingestion workflow. It enables users to:

*   Initiate new material ingestion runs.
*   Check the status of ongoing or completed runs.
*   Retrieve visualizations related to pipeline execution.
*   Access detailed reports generated by the pipeline.

The API is built using FastAPI, ensuring high performance and automatic OpenAPI specification generation (accessible at `/docs` or `/redoc` when the application is running).

## 2. Base URL

`http://localhost:8000` (assuming default local deployment)

## 3. Authentication

All protected API endpoints require authentication using an API Key. The key must be provided in the `X-API-Key` header.

**Header Name**: `X-API-Key`
**Example Key**: `your-super-secret-api-key` (Note: In a production environment, this key must be loaded from secure environment variables or a secret management system).

```bash
curl -X GET "http://localhost:8000/pipeline/status/a1b2c3d4-e5f6-7890-1234-567890abcdef" \
     -H "X-API-Key: your-super-secret-api-key"
```

## 4. Error Handling

The API uses a standardized JSON error response format for all errors, including validation errors, authentication failures, and internal server errors. This format aligns with the `ApiError` Pydantic model and `ApiError` TypeScript interface.

**Error Response Structure:**

```json
{
  "code": "string",
  "message": "string",
  "details": {
    "field": "string",
    "reason": "string"
  }
}
```

**Example Error Response (Validation Error):**

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid input provided for materialId.",
  "details": {
    "field": "materialId",
    "reason": "value is not a valid uuid"
  }
}
```

## 5. Data Models

The API leverages Pydantic models for robust data validation and clear contract definition. These models are mirrored by TypeScript interfaces in `shared-api-contracts.ts` for client-side consistency.

### `ApiError`

Represents a standardized error response.

| Field   | Type                     | Description                                            | Example                                   |
| :------ | :----------------------- | :----------------------------------------------------- | :---------------------------------------- |
| `code`  | `string`                 | A unique code identifying the error type.              | `VALIDATION_ERROR`                        |
| `message` | `string`                 | A human-readable message describing the error.         | `Invalid input provided for materialId.`  |
| `details` | `object` (optional)      | Additional details, often for validation errors.       | `{"field": "materialId", "reason": "must be a UUID"}` |

### `PipelineRunRequest`

Request payload for initiating a new pipeline run.

| Field         | Type                     | Description                                                               | Example                                   |
| :------------ | :----------------------- | :------------------------------------------------------------------------ | :---------------------------------------- |
| `materialId`  | `string`                 | Unique identifier for the material to be ingested.                        | `a1b2c3d4-e5f6-7890-1234-567890abcdef`    |
| `sourceType`  | `string`                 | Type of the source material (e.g., 'web_crawl', 'document_upload').       | `web_crawl`                               |
| `configuration` | `object`                 | Flexible configuration object for the pipeline run.                       | `{"url": "http://example.com", "depth": 2}` |
| `priority`    | `integer` (optional)     | Priority for the pipeline run (1-100, default: 10).                       | `50`                                      |
| `callbackUrl` | `string` (optional)      | URL for status updates during the pipeline run.                           | `http://your-service.com/webhook`         |

### `PipelineRunResponse`

Response after successfully initiating a pipeline run.

| Field       | Type                     | Description                                            | Example                                   |
| :---------- | :----------------------- | :----------------------------------------------------- | :---------------------------------------- |
| `runId`     | `string`                 | Unique identifier for the initiated pipeline run.      | `f1e2d3c4-b5a6-9876-5432-10fedcba9876`    |
| `status`    | `string`                 | Current status of the pipeline run.                    | `QUEUED`                                  |
| `message`   | `string`                 | A descriptive message about the run initiation.        | `Pipeline run initiated successfully.`    |
| `timestamp` | `string` (ISO 8601)      | Timestamp of when the run was initiated.               | `2023-10-27T10:00:00.123456`              |

### `PipelineStatusResponse`

Represents the status of an ongoing or completed pipeline run.

| Field         | Type                     | Description                                                               | Example                                   |
| :------------ | :----------------------- | :------------------------------------------------------------------------ | :---------------------------------------- |
| `runId`       | `string`                 | Unique identifier for the pipeline run.                                   | `f1e2d3c4-b5a6-9876-5432-10fedcba9876`    |
| `status`      | `string`                 | Current status of the pipeline run (`QUEUED`, `RUNNING`, `FAILED`, `COMPLETED`, `CANCELLED`). | `RUNNING`                                 |
| `progress`    | `integer`                | Percentage completion (0-100).                                            | `75`                                      |
| `currentStage` | `string` (optional)      | Current stage of the pipeline (e.g., 'Extraction', 'Validation').         | `Embedding`                               |
| `details`     | `object` (optional)      | Additional details about the current stage or overall run.                | `{"processed_items": 150, "total_items": 200}` |
| `errors`      | `array` of `ApiError` (optional) | List of errors encountered during the run.                                | `[{"code": "EXTRACTION_ERROR", "message": "Failed to parse document."}]` |
| `startTime`   | `string` (ISO 8601)      | Timestamp of when the run started.                                        | `2023-10-27T10:00:00.123456`              |
| `endTime`     | `string` (ISO 8601, optional) | Timestamp of when the run completed or failed.                            | `2023-10-27T10:15:30.789012`              |

### `PipelineVisualizationResponse`

Response containing visualization data for a pipeline run.

| Field             | Type                     | Description                                                               | Example                                   |
| :---------------- | :----------------------- | :------------------------------------------------------------------------ | :---------------------------------------- |
| `runId`           | `string`                 | Unique identifier for the pipeline run.                                   | `f1e2d3c4-b5a6-9876-5432-10fedcba9876`    |
| `visualizationType` | `string`                 | Type of visualization (`graph`, `mermaid`, `image_url`).                  | `mermaid`                                 |
| `data`            | `string`                 | Graph definition (e.g., Mermaid syntax), base64 image, or URL.            | `graph TD; A-->B; B-->C;`                 |
| `description`     | `string` (optional)      | A description of the visualization.                                       | `Flow of data through the pipeline stages.` |

### `PipelineReportResponse`

Response containing a detailed report for a pipeline run.

| Field           | Type                     | Description                                                               | Example                                   |
| :-------------- | :----------------------- | :------------------------------------------------------------------------ | :---------------------------------------- |
| `runId`         | `string`                 | Unique identifier for the pipeline run.                                   | `f1e2d3c4-b5a6-9876-5432-10fedcba9876`    |
| `reportFormat`  | `string`                 | Format of the report (`json`, `pdf`, `html`).                             | `json`                                    |
| `reportContent` | `object` or `string`     | JSON object for `json` format, or URL/base64 content for other formats.   | `{"summary": "Success", "extracted_items": 100}` |
| `generatedAt`   | `string` (ISO 8601)      | Timestamp of when the report was generated.                               | `2023-10-27T10:20:00.987654`              |

### 6.3. Start Pipeline Run

**POST** `/pipeline/run`

*   **Description**: Initiates a new material ingestion pipeline run as a background task. The API immediately returns a `runId` for tracking.
*   **Authentication**: Required (API Key).
*   **Request Body**: `PipelineRunRequest`
*   **Responses**:
    *   `202 Accepted`: `PipelineRunResponse` - Pipeline run successfully queued.
    *   `400 Bad Request`: `ApiError` - Invalid input data.
    *   `401 Unauthorized`: `ApiError` - Missing or invalid API Key.

**Example Request:**

```bash
curl -X POST "http://localhost:8000/pipeline/run" \
     -H "X-API-Key: your-super-secret-api-key" \
     -H "Content-Type: application/json" \
     -d '{
           "materialId": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
           "sourceType": "web_crawl",
           "configuration": {
             "url": "https://example.com/document",
             "depth": 1,
             "extract_images": true
           },
           "priority": 20,
           "callbackUrl": "http://your-service.com/pipeline-status-webhook"
         }'
```

**Example Response:**

```json
{
  "runId": "f1e2d3c4-b5a6-9876-5432-10fedcba9876",
  "status": "QUEUED",
  "message": "Pipeline run initiated successfully.",
  "timestamp": "2023-10-27T10:00:00.123456"
}
```

### 6.4. Get Pipeline Status

**GET** `/pipeline/status/{run_id}`

*   **Description**: Retrieves the current status and progress of a specific pipeline run.
*   **Authentication**: Required (API Key).
*   **Path Parameters**:
    *   `run_id` (string, required): The unique identifier of the pipeline run.
*   **Responses**:
    *   `200 OK`: `PipelineStatusResponse` - Current status of the run.
    *   `401 Unauthorized`: `ApiError` - Missing or invalid API Key.
    *   `404 Not Found`: `ApiError` - Pipeline run with the given `run_id` not found.

**Example Request:**

```bash
curl -X GET "http://localhost:8000/pipeline/status/f1e2d3c4-b5a6-9876-5432-10fedcba9876" \
     -H "X-API-Key: your-super-secret-api-key"
```

**Example Response:**

```json
{
  "runId": "f1e2d3c4-b5a6-9876-5432-10fedcba9876",
  "status": "RUNNING",
  "progress": 60,
  "currentStage": "Validation",
  "details": {
    "validated_documents": 5,
    "total_documents": 8
  },
  "errors": [],
  "startTime": "2023-10-27T10:00:00.123456"
}
```

### 6.5. Get Pipeline Visualization

**GET** `/pipeline/visualize/{run_id}`

*   **Description**: Retrieves visualization data for a completed pipeline run, such as a Mermaid graph or an image URL.
*   **Authentication**: Required (API Key).
*   **Path Parameters**:
    *   `run_id` (string, required): The unique identifier of the pipeline run.
*   **Responses**:
    *   `200 OK`: `PipelineVisualizationResponse` - Visualization data.
    *   `401 Unauthorized`: `ApiError` - Missing or invalid API Key.
    *   `404 Not Found`: `ApiError` - Pipeline run or visualization data not found.
    *   `409 Conflict`: `ApiError` - Visualization not available for the current run status (e.g., still running).

**Example Request:**

```bash
curl -X GET "http://localhost:8000/pipeline/visualize/f1e2d3c4-b5a6-9876-5432-10fedcba9876" \
     -H "X-API-Key: your-super-secret-api-key"
```

**Example Response:**

```json
{
  "runId": "f1e2d3c4-b5a6-9876-5432-10fedcba9876",
  "visualizationType": "mermaid",
  "data": "graph TD; A[Start]-->B(Extract); B-->C{Validate}; C--OK-->D[Embed]; C--Fail-->E[Error]; D-->F[Complete];",
  "description": "Workflow of the material ingestion pipeline for this run."
}
```

### 6.6. Get Pipeline Report

**GET** `/pipeline/report/{run_id}`

*   **Description**: Retrieves a detailed report for a completed pipeline run.
*   **Authentication**: Required (API Key).
*   **Path Parameters**:
    *   `run_id` (string, required): The unique identifier of the pipeline run.
*   **Responses**:
    *   `200 OK`: `PipelineReportResponse` - Detailed report data.
    *   `401 Unauthorized`: `ApiError` - Missing or invalid API Key.
    *   `404 Not Found`: `ApiError` - Pipeline run or report not found.
    *   `409 Conflict`: `ApiError` - Report not available for the current run status (e.g., still running).

**Example Request:**

```bash
curl -X GET "http://localhost:8000/pipeline/report/f1e2d3c4-b5a6-9876-5432-10fedcba9876" \
     -H "X-API-Key: your-super-secret-api-key"
```

**Example Response:**

```json
{
  "runId": "f1e2d3c4-b5a6-9876-5432-10fedcba9876",
  "reportFormat": "json",
  "reportContent": {
    "overall_status": "COMPLETED",
    "extracted_items": 100,
    "validated_items": 98,
    "failed_items": 2,

      {"code": "VALIDATION_ERROR", "count": 2}
```
